# Wallet API reference

[English home](../../README.en.md) · [Architecture](ARCHITECTURE.md)

## Read a report

```http
GET /api/v1/assets/{wallet_address}?refresh=false
```

`refresh=true` skips stored reports. It can join an already-running read in the same process; it does not guarantee a separate RPC call or a chain state newer than another response.

For a running local API, substitute a wallet you want to query:

```bash
curl --fail-with-body 'http://localhost:8000/api/v1/assets/YOUR_WALLET_PUBLIC_KEY?refresh=true'
```

This command uses the configured live RPC/price providers. For deterministic synthetic data instead, run the [offline demo](DEMO.md).

## Response fields

| Field                                                                 | Meaning                                                            |
| --------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `wallet_address`                                                      | Queried wallet                                                     |
| `quantity_schema_version`                                             | 2                                                                  |
| `account_identity_version`                                            | 1                                                                  |
| `sol_balance_raw`, `sol_decimals`, `sol_balance_exact`                | Lamport integer string, scale 9, fixed-point SOL string            |
| `token_observed_slot`                                                 | Token read-context u64 string; `null` when the token list is empty |
| `tokens[].balance_raw`                                                | Canonical unsigned decimal u64 string                              |
| `tokens[].decimals`                                                   | Integer scale in 0..255                                            |
| `tokens[].balance_exact`                                              | Fixed-point text derived from raw units and scale                  |
| `tokens[].account_address`, `token_owner`, `program_id`               | Account identity; list keys use program and account                |
| `tokens[].observed_slot`                                              | Read-context u64 string, not an account write version              |
| `tokens[].symbol`, `name`, `mint`                                     | Token display/identity data                                        |
| `balance`, `sol_balance`, `price_usd`, `value_usd`, `total_value_usd` | Existing approximate numeric compatibility fields                  |
| `report_context`                                                      | Read-window and publication metadata described below               |

The service preserves known zero records. Missing/invalid required input does not produce a fabricated zero success. An absent quote is still represented by legacy zero-valued USD fields in some paths, so those fields cannot distinguish missing valuation from known zero valuation.

## Report context

Timestamps are millisecond integer strings; age and budget are safe nonnegative/positive integer numbers. Required context includes:

- `schema_version=1`, `freshness_scope="account-read-window"`.
- `source="rpc_read"` or `"report_cache"`.
- `network`, `commitment="confirmed"`, `configured_source_id` and `account_scope="native-sol+legacy-token"`.
- `read_started_at_ms`, `read_completed_at_ms`, `served_at_ms`, `age_ms`, `max_age_ms`.
- `joined_refresh` and `publication_status`.

A report is eligible only while `age_ms < max_age_ms`. Cache hits preserve the read start. Reaching the boundary expires it. These fields describe the account read window, not price freshness or chain finality. A network label describes configuration rather than verifying the remote network.

| Publication status | Meaning                                                                           |
| ------------------ | --------------------------------------------------------------------------------- |
| `published`        | Redis confirmed the reservation-matched write                                     |
| `cache_hit`        | A valid stored report was returned                                                |
| `skipped`          | No confirmed reservation; a valid read can be returned without shared publication |
| `unknown`          | Publication reply failed; the write may or may not have executed                  |

## Errors

- **503:** report read budget/freshness policy failed, clock moved backwards, or the publication reservation expired/was superseded. Retry according to the caller's bounded policy; do not treat it as a zero balance.
- **500:** other errors on the wallet read, parsing or formatting path. A request can fail as a whole when one required account record is invalid.
- **422:** request parameter validation errors handled by FastAPI, such as an invalid boolean query value.

No separate stable public error-code enum or specific 400 classification for malformed wallet keys is added here. The route's present generic 500 path can include upstream validation errors.

## Other API areas

The application also registers `/api/v1/auth`, `/strategy`, `/chat`, `/risk`, `/transactions`, `/defi` and `/knowledge`. Their current schemas are available at `/openapi.json` when the API is running. This document does not certify those workflows. In particular, auth login/verify are TODO implementations, and AI-dependent requests may be unavailable without the optional agent environment.

The separate [swap quote contract](QUOTE_CONTRACT.md) now requires `amount_raw` as positive u64 integer text. The old float `amount` request is rejected with 422; callers must migrate. Provider response mismatches return 502. This is a quote-only boundary, not transaction authorization or a live-execution certificate.
